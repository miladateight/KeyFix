# KeyFix 1.0.0

KeyFix is stable. 0.7.0 completed the intelligence work but shipped as a pre-release because it had not been lived with yet; it has now, and 1.0.0 is the first release without that caveat.

Three features are new, along with a dictionary bug that turned out to be affecting every spelling decision.

## New in 1.0.0

### AutoCorrect

AutoCorrect fixes high-confidence single-token misspellings — `recieve` to `receive`, `شلام` to `سلام` — without requiring full spelling detection to be enabled first. Spelling detection remains the broader, more talkative feature; AutoCorrect is the narrow one that just fixes the obvious cases quietly.

It is off by default. When enabled it passes through the same confidence threshold and ambiguity margin as every other correction, so a word with two equally plausible candidates is still only ever a suggestion. Protected tokens — URLs, emails, paths, versions, code identifiers — are untouched, as before.

### QR code from the current selection

`Ctrl+Shift+Q` turns whatever is selected in the focused application into a QR code. A small dialog shows the code and offers **Save as PNG**.

There is no supported way to read another application's selection, so KeyFix copies it, reads the clipboard, and puts the previous clipboard contents back. The selected text is used only to render a local image: it is never uploaded, logged or stored. QR codes are generated on the machine with QRCoder.

The shortcut can be changed from Settings or switched off entirely with **Enable the global QR-code shortcut**, for anyone whose applications already own that binding. A shortcut needs at least one modifier and one supported key (`A`-`Z`, `0`-`9`, `F1`-`F12`, `Space`, `Insert`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`); Settings rejects anything else instead of silently rebinding.

Selections too large for a QR symbol, and selections that cannot be read at all, now report a tray notification instead of failing silently.

### Update checker

KeyFix checks the public GitHub Releases API once a day and shows a tray balloon when a newer version exists; clicking the balloon opens the release page.

The request is read-only and anonymous. It sends no typed text, no telemetry and no account information, and it downloads nothing automatically. The check is re-evaluated hourly while KeyFix is resident, so a release published during a long session is still noticed. It can be turned off, and the interval changed, in Settings.

### Larger dictionaries

The embedded word lists gained additional high-frequency words for English, Persian, Arabic and German.

## Fixes

- **The supplementary word lists were loading before the main ones.** Rank is insertion position, so the supplementary lists claimed the top frequency ranks and demoted the genuinely most common words — `the` fell from rank 0 to rank 49. That skewed every frequency-weighted spelling decision downstream: `teh` was being "corrected" to `ten` instead of `the`. The main frequency-ordered list is now loaded first, and the extra list only contributes words the main one is missing.
- **Equal-distance spelling candidates came back in an unstable order.** The lookup used `List<T>.Sort`, an unstable introsort, so which same-distance candidates survived the result-limit trim varied between identical calls.
- **The QR shortcut synthesized `Ctrl+Shift+C` instead of `Ctrl+C`.** The modifiers of the triggering hotkey were still physically held, so the copy step arrived as an unrelated command — developer tools, in a browser — and the capture returned nothing. Held modifiers are released first now.
- **Generating a QR code from an oversized selection crashed the app.** The failure happened on a background thread, where an unhandled exception terminates the process rather than showing a message.
- **Holding the QR shortcut opened one dialog per key auto-repeat.** The binding is latched for the duration of the press.
- **Hotkey matching now requires an exact modifier match.** `Ctrl+Shift+Alt+Q` no longer fires a `Ctrl+Shift+Q` binding and steals a shortcut the focused application owns.

## Performance

- `TextRingBuffer` caches its typed-text snapshot, so repeated reads no longer re-materialize the buffer on every property access.
- `SymSpellIndex.Lookup` reuses a list and sorts explicitly instead of allocating per lookup through LINQ.
- `FrequencyDictionary` loads each language lazily, so startup only pays for the languages actually in use.

## Settings

The settings schema moves to version 9. Migration preserves every existing choice and adds conservative defaults for AutoCorrect (off), update checking (on, daily) and the QR-code hotkey (`Ctrl+Shift+Q`). A hotkey value that would not install as a usable shortcut is replaced with the default rather than left broken.

## Known limitations

- **Real-world accuracy has not been independently measured.** The evaluation corpus is small and hand-written; its results on that corpus are not a general accuracy claim.
- **SymSpell index memory cost is known and non-trivial.** Building the English spelling index takes roughly 1.2 seconds and allocates on the order of 300 MB the first time spelling detection is used for that language — lazily, once per language, not per keystroke.
- **The bigram context model only has data for English.** Persian, Arabic and German get a neutral context score.
- **Arabic support is limited to letter and diacritic normalization.** There is no prefix/suffix analysis of the kind Persian half-space reconstruction does.
- **German compound-word handling is limited** to not flagging an absent compound as misspelled.
